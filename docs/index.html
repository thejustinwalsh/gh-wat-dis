Agent skills for GitHub issues, pull requests and milestones

Read an issue in two minutes and know what to do.

gh-wat-dis is a set of skills for the coding agent that writes your issues and pull requests. Each one opens with the problem and the solution, then shows what changes in the system, and takes its claims about the code from tools that read the repository.

Say this to your coding agent

Run npx gh-wat-dis install, then tell me how to use it.

The agent runs every tool through npx, so your project gains no dependency.

The shape

Every issue answers the same five questions, in the same order.

Readers learn where to look. The agent leaves out a section that has nothing true to say.

The tools

Tools the agent runs before it makes a claim about the code.

Each tool does one thing and prints JSON, so the agent can chain them and write only what a tool reported. For TypeScript, JavaScript and Rust, impact names the changed functions and the files that import them.

The diagrams

A system diagram in the issue, drawn to fit GitHub’s 860-pixel column.

A JSON spec goes in and an SVG comes out. A diagram can show services, or the inside of one browser tab: threads, workers, WASM modules and the protocols between them. Each status has its own border and badge, so colour is never the only signal.

The skills

Ask in plain words.

Eight skills trigger on the task, and one entry skill checks the repo policy first. The agent shows you the draft before it posts.

wat-issue
“File an issue for the duplicate charge bug.”
wat-pr

wat-milestone
“Where are we on v1.4?”
wat-triage
“Triage the new issues and tell me what belongs in v1.4.”
wat-maintain
“Run a backlog cleanup.”
wat-architecture
“What does this change affect?”
wat-diagram
“Draw the container diagram for checkout.”
wat-setup
“Set up gh-wat-dis and the GitHub MCP server.”

Works in

Claude Code, Codex, Cursor, Gemini CLI, OpenCode and Copilot.

One install puts the skills where each harness looks. A config file in the repository tells every agent whether to use them.

Scope

It reports what a change does and leaves the verdict to the reviewer.

Your repository sets the coding style, the test policy and the branch rules. gh-wat-dis decides how to communicate the work.
