Agent skills for GitHub issues, pull requests and milestones

Read an issue in two minutes and know what to do.

gh-wat-dis is a set of skills for the coding agent that writes your issues and pull requests. Each one opens with the problem and the solution, then shows what changes in the system, and takes its claims about the code from tools that read the repository.

Say this to your coding agent

Let's install gh-wat-dis in this project, then tell me how to use it

The agent adds one dev dependency and runs every tool through npx.

The shape

Every issue answers the same five questions, in the same order.

Readers learn where to look. The agent leaves out a section that has nothing true to say.

The tools

Tools the agent runs before it makes a claim about the code.

Each tool does one thing and prints JSON, so the agent can chain them and write only what a tool reported. For TypeScript, JavaScript and Rust, impact names the changed functions and the files that import them.

impact

Collects what a change touches and who depends on it.

→ facts.json
graph from-facts

Turns the facts into a diagram spec.

→ spec.json
graph focus

Keeps the changed parts and one hop around them.

→ spec.json
diagram

Draws an SVG that fits GitHub's width.

→ change.svg
gh --attach

Uploads it with the issue or pull request.

→ github.com
reach
Lists what depends on a file or symbol, before any code changes.
related
Finds issues and PRs that share an error, a symbol or a path with a draft.
links
Shows what a PR closes on merge and what it only mentions.
graph split
Writes an overview and one small diagram for each part that changes.
legend
Prints a diagram's relationships as a Markdown table.
doctor
Checks gh, the sign-in, the skills, the MCP server, the repo config and the optional tools. Each line says ok, FIX or off.

Set up

install
Set up gh-wat-dis in one step: copy the wat skills to where each agent harness looks, write this repository's config when it has none, then run the doctor checks. writes local files
uninstall
Remove the skill directories this package installed. writes local files
init
Write the repository config at .agents/gh-wat-dis/config.json again. install writes it the first time; use this with --force for a fresh one. writes local files
mcp
Print the GitHub MCP server config for a harness, or write it for every harness found here. Stores no token. writes local files
doctor
Check the runtime, gh, the skills, the GitHub MCP server, the config and the optional tools. Offers a fix where it has one, and installs an optional tool when asked. writes local files

Collect facts (JSON out)

impact
Facts about a change: files, changed symbols, dependents, elements, contracts, owners, files that usually change together, and complexity moved (when cccc is installed). Each fact names its source.
reach
Who depends on a file or an exported symbol. Needs no diff.
owners
CODEOWNERS for paths, with the rule that matched.
elements
The architecture elements and the files each one maps, from the config or from the workspace layout.
issues
Open issues with type, surfaces, milestone, tracking flag and what each one is missing.
survey
What a repository with history holds before a migration: open issues by what they lack, facts on their bodies, labels outside the plan, open milestones. --issues prints the next batch.
related
Issues and pull requests that share an error, an identifier, a file path or title words with a draft or an issue. Reports signals. It does not decide what is a duplicate.
links
Which issues a pull request closes on merge and which it only mentions, from the body and the commit messages. Exits non-zero when that differs from --closes.
relations
An issue's parent, sub-issues, blocked by and blocking, from GitHub's native relations.
milestone
A rating for a milestone with every measured signal behind it, and the status numbers: counts, what is in review, what is blocked, the done-when conditions, the tracking issue. No dates.
audit
The maintenance checks that can be counted: stale issues and pull requests, missing fields, milestones, orphan pull requests, done but open, labels, blocked chains. One finding for each item, with the reason.
labels
The agents, surface, priority, size and type labels the config wants, compared with the labels on GitHub.

Change GitHub

relate
Set or remove a native relation between issues: parent, blocked by, blocks. A new parent replaces the old one. writes to GitHub
labels apply
Create and update the labels the config wants. --prune also deletes the others. writes to GitHub

Shape a graph (diagram spec in, diagram spec out)

graph from-facts
A diagram spec from impact facts: the changed and reached elements with their status. --level file gives a code diagram: files as cards, changed symbols as rows.
graph from-config
A diagram spec of the whole architecture map in the repository's config.
graph focus
Keep some elements, their neighbours within N hops, and every ancestor.
graph collapse
Fold everything inside an element into it and merge the relationships.
graph drop
Remove elements and their relationships.
graph merge
The union of several specs. Later files win field by field.
graph diff
One spec that marks what was added, removed and changed between two specs.
graph set
Edit fields of the spec, of elements or of relationships. "key=" deletes the key.
graph rename
Rename an element id everywhere in a spec.
graph split
Write an overview spec plus one small spec for each changed group. writes local files
graph stats
Counts for a spec: elements, relationships, by type, by status, depth.
graph ids
One line for each element: id, type, status, name.

Render

diagram
Lint a diagram spec and draw it as an SVG in the form of its type, loosened one rung at a time until it fits GitHub's width. --png adds a PNG to look at. --report prints the judgement as JSON. writes local files
legend
A spec's relationships as a Markdown table, to sit under a diagram with numbered lines.
blast
Impact facts as a Markdown "Blast radius" section: what the change reaches outside its diff, with file links.

Check

lint
Backstop check of a body before it is posted: what GitHub would break, and gross shape errors. It does not judge wording.

The diagrams

A system diagram in the issue, drawn to fit GitHub’s 860-pixel column.

A JSON spec goes in and an SVG comes out. A diagram can show services, or the inside of one browser tab: threads, workers, WASM modules and the protocols between them. Each status has its own border and badge, so colour is never the only signal.

The skills

Ask in plain words.

Ten skills. Nine trigger on the task, and the entry skill, wat, checks the repo policy first. The agent shows you the draft before it posts.

wat-issue
“File an issue for the duplicate charge bug.”
wat-pr
“Open a PR for this branch.”
wat-milestone
“Where are we on v1.4?”
wat-triage
“Triage the new issues and tell me what belongs in v1.4.”
wat-maintain
“Run a backlog cleanup.”
wat-architecture
“What does this change affect?”
wat-diagram
“Draw the container diagram for checkout.”
wat-setup
“Set up gh-wat-dis and the GitHub MCP server.”
wat-migrate
“Migrate this repo and its open issues to gh-wat-dis.”

Works in

Claude Code, Codex, Cursor, Gemini CLI, OpenCode and Copilot.

One install puts the skills where each harness looks. A config file in the repository tells every agent whether to use them.

Scope

It reports what a change does and leaves the verdict to the reviewer.

Your repository sets the coding style, the test policy and the branch rules. gh-wat-dis decides how to communicate the work.
